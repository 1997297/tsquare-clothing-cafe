## RLS

Customer access model verified from live grants and policies:

- profiles: customer can read only their own row and update only first name, last name, phone, preferred contact, avatar URL, and updated timestamp.
- measurement_profiles: customer can read only their own history. Direct customer insert/update/delete is blocked.
- bespoke_requests: customer can read only their own requests. Direct customer insert/update/delete is blocked.
- orders: customer can read only their own orders. Direct insert/update/delete is blocked.
- appointments: customer can read only their own appointments. Direct operational mutation is blocked.
- saved_styles: customer can read, insert, and delete only their own saved styles.
- notifications: customer can read only their own notifications and update only is_read/read_at. Content and identity fields cannot be changed.
- payments: customer can read only their own payments. Direct insert/update/delete is blocked.
- wardrobe_items: customer can read only their own wardrobe. Direct insert/update/delete is blocked.
- concierge_requests and concierge_messages: customer can read only owned threads. Direct writes are blocked and use trusted server operations.
- appointment_change_requests: customer can read only owned requests. Direct insert/update is blocked and trusted requests start pending review.
- lifecycle_events: customer can read only their own events and cannot write them.
- contact_enquiries and public_fitting_requests: anon/authenticated roles have no direct table privileges; trusted server intake writes are used.
