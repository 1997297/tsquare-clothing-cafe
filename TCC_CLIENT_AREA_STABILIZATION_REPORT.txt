TCC CLIENT AREA — REPAIR & UX STABILIZATION REPORT
Completed: 27 September 2026

OUTCOME

The client-area stabilization pass is complete. Booking persistence, appointments,
Saved Looks, favourites, profile persistence, avatar storage, navigation, theme
support, local imagery, loading feedback, and the identified route-performance
issues were repaired without replacing the existing TCC architecture or visual
identity.

ROOT CAUSES AND REPAIRS

1. Book-a-fitting navigation
   Root cause: the public booking screen and its success state had no explicit
   authenticated return route.
   Repair: introduced one reusable ReturnLink component and added explicit dashboard,
   appointment, and contextual parent links throughout the affected client and detail
   screens.

2. Fitting requests missing from Atelier Appointments
   Root cause: the form wrote only to public_fitting_requests while the client portal
   reads appointments. The two records were not atomically linked to the authenticated
   profile.
   Repair: added a service-role-only submit_public_fitting_request RPC. It writes the
   intake row, canonical appointment, lifecycle event, and relationship in one database
   transaction. The server action passes the authenticated profile ID and returns the
   new appointment ID. Requested sessions now open by default and display date, time,
   location, and status.

3. Favourites and Saved Looks
   Root cause: saved state was fragmented and could hydrate from guest localStorage even
   when Supabase was configured. This caused a successful database save to disappear
   after refresh. Duplicate Saved Looks fetching also existed.
   Repair: installed one global SavedStylesProvider backed by saved_styles for signed-in
   clients. It supports optimistic add/remove, rollback, guest-to-account migration,
   deduplication, loading, empty, and visible error states. Demo mode is now impossible
   when a real Supabase project is configured.

4. Profile persistence
   Root cause: the profile form could initialize before the asynchronous profile query
   finished and did not rehydrate. Updates also did not replace client state with the
   canonical returned database row.
   Repair: profile queries are deduplicated, profile/session loading is coordinated, the
   form rehydrates when profile data arrives, and updates return and install the saved
   row. Booking contact fields also prefill from the authenticated profile.

5. Profile avatar
   Root cause: no storage bucket, owner-scoped policies, upload workflow, or reusable
   avatar display existed.
   Repair: added a public profile-avatars bucket with a 5 MB limit and JPEG/PNG/WebP
   allow-list. SELECT/INSERT/UPDATE/DELETE policies enforce the authenticated user's
   top-level folder and ownership. Upload, replacement, cleanup, validation, error and
   loading states, persistent profile URL, and initials fallback are implemented.

6. Navigation delay
   Root cause: the account provider could load the full private-account dataset on
   public routes, Saved Looks was queried twice, profile work was repeated, and remote
   image requests added another dependency. Several routes also lacked an intentional
   loading state.
   Repair: private account data is loaded only for account and bespoke-create routes;
   independent work is parallelized; profile queries are deduplicated; Saved Looks has
   one source of truth; Next Link/router navigation is retained; public routes no longer
   trigger the private multi-table load; and the account area has a lightweight loading
   skeleton.

7. Theme and date picker
   Root cause: the interface was effectively hard-coded to dark surface colours and had
   no persistent theme owner. The native date indicator did not receive an appropriate
   browser colour scheme.
   Repair: added a global ThemeProvider, accessible desktop/mobile toggles, persisted
   preference, a pre-hydration theme script, shared RGB theme tokens, and light-theme
   coverage for surfaces, forms, navigation, drawers, cards, statuses, buttons, and
   account screens. The date input uses the active colour-scheme and theme-aware icon
   treatment.

8. External imagery and image warnings
   Root cause: five active images still depended on Unsplash/Wikimedia, and some fill
   images lacked a positioned parent or sizes metadata.
   Repair: downloaded the exact active assets into public/images/styles and
   public/images/atelier, replaced every external image reference, removed obsolete
   Next Image host configuration, and corrected fill parents/sizes. Normal site image
   rendering now uses local assets (apart from the authenticated Supabase avatar URL).

DATABASE / RLS / STORAGE

  supabase/migrations/20260925060816_client_area_stabilization.sql

Changes:
  - public_fitting_requests.appointment_id UUID foreign key to appointments.id
  - partial unique index preventing duplicate appointment linkage
  - atomic public.submit_public_fitting_request(uuid, jsonb) RPC
  - RPC execution revoked from public, anon, and authenticated; granted to service_role
  - profile-avatars storage bucket, public read URL, 5 MB limit, image MIME allow-list
  - owner-folder SELECT/INSERT/UPDATE/DELETE storage policies

The migration was pushed to the linked Supabase project. No manual SQL remains for the
currently linked project. A different environment must run the committed migrations in
order (for example, with supabase db push).
